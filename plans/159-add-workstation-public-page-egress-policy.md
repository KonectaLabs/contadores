## Why This Matters

Workstation public trial pages are generated by Codex and then served to leads. The file allowlist can prevent local metadata leaks, but generated HTML/JS can still reference remote scripts, fonts, frames, analytics, or media unless response headers and generation instructions forbid that egress.

Public trial pages should be self-contained and served with a strict browser policy: no remote scripts, no referrer leakage, no powerful browser permissions, and only local page assets.

## Steps

### Step 1: Define the browser policy

Use a restrictive CSP shape, for example:

```text
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
font-src 'self' data:;
connect-src 'none';
frame-src 'none';
object-src 'none';
base-uri 'none';
form-action 'none';
```

Adjust only if generated pages have a documented need.

### Step 2: Apply headers consistently

Add a helper that wraps public Workstation `FileResponse` objects with:

- CSP,
- Referrer-Policy,
- Permissions-Policy,
- any cache headers from plan 113 if already landed.

Apply it to HTML and asset routes.

### Step 3: Update generation instructions

In the solo-page generation prompt and skill docs, require:

- no remote scripts,
- no external fonts,
- no analytics pixels,
- no iframes,
- no external image/video URLs,
- all required assets under `assets/`.

### Step 4: Add tests

Create a public page fixture and assert:

- `/p/{token}/` has CSP/referrer/permissions headers,
- `/p/{token}/styles.css` or an allowed asset has the same relevant headers,
- CSP contains `connect-src 'none'` and `frame-src 'none'`.
